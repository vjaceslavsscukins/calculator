# kitchen-api

Сервер между приложением и Битрикс24. Ключ вебхука хранится только здесь, в переменной окружения. Читает данные из Битрикса и отдаёт их по Bearer-токену, писать в Битрикс не может. Второе назначение: общая база проектов для тестирования (раздел ниже).

## Запросы (все GET, заголовок `Authorization: Bearer <RELAY_TOKEN>`)

- `/healthz` — проверка, что сервис жив (без токена).
- `/bitrix/<метод>?<параметры>` — вызов метода REST, например `/bitrix/crm.deal.list?filter[STAGE_ID]=C1:WON&select[]=ID&select[]=TITLE`.
  Разрешены только методы чтения (`list`, `get`, `getlist`, `getchildren`, `getfields`, `fields`, `getdata`, `getbyid`) из разделов `crm`, `disk`, `tasks`, `task`, `sonet_group`, `socialnetwork`, `lists`. Из чата открыты ровно два метода: `im.dialog.messages.get` (сообщения и файлы чата задачи, `DIALOG_ID=chat<chatId>`) и `im.dialog.get`. Параметры `auth` и `token` отбрасываются.
- `/bitrix-file/<id файла на Диске>` — скачать файл с Диска (до 25 МБ).

## Общая база проектов (для тестирования)

У каждого человека личный код доступа, проекты видны только ему: чужой проект выглядит как несуществующий (404), в том числе для администратора. Заголовок `Authorization: Bearer <код>`. Доступ из браузера (CORS) только с адресов из `ALLOWED_ORIGINS`.

Люди (только главный код `PROJECTS_TOKEN`, не короче 16 знаков):
- `GET /users` — список людей (имя, дата, отключён ли).
- `POST /users` `{name}` — завести человека. В ответе его код **один раз**: в базе хранится только отпечаток (SHA-256), восстановить код нельзя.
- `POST /users/<id>/code` — выдать новый код (старый перестаёт работать).
- `DELETE /users/<id>` — отключить (проекты остаются).
- `GET /me` — кто я: `{name, role}` (подходит любому коду).

Проекты (только личный код; у главного кода проектов нет):
- `GET /projects` — мои проекты без данных: `id`, `name`, `client`, `order`, `total`, `rev`, `updatedAt`, `updatedBy`.
- `POST /projects` — создать. Тело: `{name, client, order, total, data}`, где `data` — состояние кухни (обязателен массив `modules`).
- `GET /projects/<id>` — проект целиком.
- `PUT /projects/<id>` — сохранить. В теле обязательна `rev` (версия, с которой начали). Если проект уже изменили (например, открыт на двух компьютерах), ответ `409` с `rev`, `updatedAt`, `updatedBy`: данные не затираются.
- `DELETE /projects/<id>` — удалить (в базе остаётся пометка `deleted_at`).
- Размер тела до 2 МБ. Имя «кто изменил» берётся из учётной записи, подделать нельзя.

Хранилище: PostgreSQL, если задан `DATABASE_URL` (таблицы создаются сами); иначе файл `PROJECTS_FILE` (на бесплатном Render диск стирается при перезапуске); без обоих `/projects` отвечает `503`. Если `DATABASE_URL` неверный или база недоступна, сервис всё равно запускается (чтение из Битрикса работает), проекты отвечают `503`, причина пишется в журнал.
Токен Битрикс-сервиса (`RELAY_TOKEN`) проекты не открывает. В проектах нет данных из Битрикса. Серверы Render стоят не в России, поэтому для тестов только вымышленные клиенты (правило 6 из `CLAUDE.md` про 152-ФЗ).

## Переменные окружения

| Имя | Что это |
| --- | --- |
| `BITRIX24_WEBHOOK_URL` | Адрес входящего вебхука `https://портал/rest/<id>/<токен>/` |
| `RELAY_TOKEN` | Токен доступа к этому серверу, не короче 24 символов (на Render создаётся сам) |
| `DATABASE_URL` | Строка подключения PostgreSQL (начинается с `postgresql://`, Render → PostgreSQL → Internal Database URL). `DATABASE_SSL=0` отключает TLS (локальная база) |
| `PROJECTS_TOKEN` | Главный код администратора: им заводят людей и выдают личные коды. Не раздавать. Не короче 16 знаков |
| `PROJECTS_FILE` | Путь к файлу с проектами, если PostgreSQL нет (только для разработки) |
| `ALLOWED_ORIGINS` | Адреса, с которых браузер может обращаться к `/projects`, через запятую (по умолчанию `https://kitchen-prototype.onrender.com`) |

## Проверки

`npm test` (Node 20+, зависимостей нет). Тесты идут против поддельного Битрикса.

Скачивание файлов проверено только на поддельном Битриксе: как настоящий портал отдаёт `DOWNLOAD_URL` для вебхуков, уточним на первом реальном файле.

В журнал пишутся только метод, путь без параметров и код ответа: в фильтрах бывают имена клиентов.
