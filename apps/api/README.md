# kitchen-api

Сервер между приложением и Битрикс24. Ключ вебхука хранится только здесь, в переменной окружения. Сейчас умеет одно: читать данные из Битрикса и отдавать их по Bearer-токену. Писать в Битрикс он не может.

## Запросы (все GET, заголовок `Authorization: Bearer <RELAY_TOKEN>`)

- `/healthz` — проверка, что сервис жив (без токена).
- `/bitrix/<метод>?<параметры>` — вызов метода REST, например `/bitrix/crm.deal.list?filter[STAGE_ID]=C1:WON&select[]=ID&select[]=TITLE`.
  Разрешены только методы чтения (`list`, `get`, `getlist`, `getchildren`, `getfields`, `fields`, `getdata`, `getbyid`) из разделов `crm`, `disk`, `tasks`, `task`, `sonet_group`, `socialnetwork`, `lists`. Из чата открыты ровно два метода: `im.dialog.messages.get` (сообщения и файлы чата задачи, `DIALOG_ID=chat<chatId>`) и `im.dialog.get`. Параметры `auth` и `token` отбрасываются.
- `/bitrix-file/<id файла на Диске>` — скачать файл с Диска (до 25 МБ).

## Переменные окружения

| Имя | Что это |
| --- | --- |
| `BITRIX24_WEBHOOK_URL` | Адрес входящего вебхука `https://портал/rest/<id>/<токен>/` |
| `RELAY_TOKEN` | Токен доступа к этому серверу, не короче 24 символов (на Render создаётся сам) |

## Проверки

`npm test` (Node 20+, зависимостей нет). Тесты идут против поддельного Битрикса.

Скачивание файлов проверено только на поддельном Битриксе: как настоящий портал отдаёт `DOWNLOAD_URL` для вебхуков, уточним на первом реальном файле.

В журнал пишутся только метод, путь без параметров и код ответа: в фильтрах бывают имена клиентов.
