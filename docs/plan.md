# Конструктор кухонь: состояние и план

Обновлено 21.10.2026. Это рабочий документ: новый чат читает его первым и продолжает с места, где остановились.

## 1. Что уже есть

Прототип `prototype/kitchen.html` (одна страница, выложена на Render как статический сайт, см. `render.yaml`). Цены в нём примерные, и по просьбе владельца пока не менялись.

**Расстановка и 3D**
- Модули ставятся только руками: перетаскивание из каталога на стену, на планшете «нажми на модуль, потом на место». Выбранный шкаф переставляется перетаскиванием. Призрак места краснеет, если не помещается.
- Панель у выбранного шкафа: ширина, стрелки, копия, удалить, открыть. Закрывается крестиком, Esc и кликом по пустому месту.
- Отмена и повтор (Ctrl+Z, Ctrl+Shift+Z), Delete, Ctrl+D, стрелки.
- Дверцы и ящики открываются по одному (двойной клик).
- Виды как в PRO100: объёмный, план сверху (контуры и номера модулей), вид спереди на каждую стену.
- Режимы как в Базис-Мебельщике: цвет, прозрачный, контуры, без фасадов.
- Меню слева сворачивается. Ползунок яркости (влияет и на печать эскиза).
- Настоящий профиль Gola и ручки-скобы, цвет чёрный, золото или серебро.

**Модули**
- 30 модулей описаны шаблонами (данные и формулы, не код). 22 исходных совпадают с первым прототипом на 600 случайных кухнях (тест).
- Библиотека модулей: свой шаблон добавляется вставкой JSON, проверяется, понятные ошибки.
- 8 новых модулей с пометкой «проверить у технолога» (под варочную, 4 ящика, открытые полки, добор нижний и верхний, низкий над вытяжкой, пенал с ящиками, открытая антресоль).

**Материалы и прайсы**
- Окно выбора с поиском и фильтрами, мастер загрузки прайса из Excel и CSV, схема столбцов запоминается по поставщику, обновление по артикулу, история цен, откат. Подробно в `docs/materials.md`.

**Документы**
- Печать КП с картинкой 3D, печать эскиза (картинка для показа), произвольные строки в смете, комплекты отделки.
- Вкладка «Технологу»: детали с размерами и кромкой, фасады, фурнитура, ведомость, эскизы по стенам, печать, выгрузка деталей в Excel.

**Битрикс24**
- `apps/api` (развёрнут на Render как `kitchen-api`): сервер только для чтения. Ключ вебхука лежит в его переменных окружения, доступ по Bearer-токену, пропускает только методы чтения. Из чата Claude доступен после настройки среды (см. раздел 5).

## 2. Чего ещё нет (главное)

- Данные хранятся в браузере (localStorage). Нет общей базы проектов, входа и ролей.
- Расчёт не проверен технологом на реальных заказах. Это главный риск (см. шаг 2).
- Нет договора, графика оплат, PDF на сервере, связи со сделкой Битрикса.
- Нет присадки, раскроя листов и выгрузки в Базис.
- Каталоги декоров без картинок: у загруженных позиций серый цвет.
- Перетаскивание на реальном планшете (долгое нажатие) не проверено, проверено только мышью.
- Прототип не заменяет рабочую систему: расчёт нужно перенести в `packages/engine` (TypeScript).

## 3. План

### Шаг 1. Битрикс и реальные данные (следующий чат)
1. Проверить доступ к `kitchen-api` из чата (раздел 5).
2. Найти, где лежат «Проекты» (Диск, смарт-процесс, сделки или задачи) и колонки «Отправленные», «Закупки», «Готово».
3. Изучить 8–10 проектов разных типов: сметы, эскизы, файлы Базиса. Обезличить (без имён, адресов, телефонов клиентов).
4. Составить «карту данных»: какие модули реально используются, какие у них размеры и фурнитура, как оформлены сметы технолога, в каком формате файлы Базиса. Записать в `docs/bitrix-findings.md`.
5. Завести недостающие модули в библиотеку (шаблонами), список вопросов к технологу оставить в `todo` шаблона.

### Шаг 2. Эталонные сметы и проверка расчёта
1. Взять 5–10 прошлых заказов с расчётом технолога, собрать в `packages/engine/fixtures` без персональных данных.
2. Прогнать через расчёт, сравнить построчно: корпус, фасады, фурнитура, работа, столешница.
3. Расхождения разобрать с технологом и превратить в правила шаблонов. Это готовность этапа 1 из ТЗ.
4. Загрузить реальные прайсы поставщиков через мастер загрузки (форматы файлов нужны от владельца).

### Шаг 3. Пилот на прототипе
- 1–2 менеджера собирают реальные проекты в прототипе параллельно с обычной работой, замечания собираем списком.
- Условие запуска: шаг 2 пройден хотя бы на 3 заказах.

### Шаг 4. Основа рабочей системы
- Монорепозиторий (pnpm или npm workspaces), `packages/engine` и `packages/schema` на TypeScript, расчёт переносится из блока CALC с теми же тестами против эталона.
- `apps/api`: PostgreSQL, пользователи и роли, общая база проектов, версии прайсов («прайс на дату»), снимок сметы, журнал изменений цен и наценок. Хостинг в России (Timeweb), правило 6.
- `apps/web`: перенос интерфейса прототипа на React и React Three Fiber, 3D строится из выхода движка.

### Шаг 5. Документы и Битрикс
- PDF КП, сметы и договор на сервере из HTML-шаблонов. Нужны шаблон договора и график оплат (открытые вопросы из ТЗ).
- Проект из сделки, сумма и документы в сделку, смена стадии. Через вебхук или локальное приложение, ключи только на сервере.

### Шаг 6. Производство
- Деталировка с присадкой, раскрой, ведомость, заказ фурнитуры, выгрузка в Базис (формат уточняем по файлам из шага 1).
- Редактор шаблонов для технолога (сейчас только вставка JSON).

## 4. Заимствуем из PRO100 (ориентир по удобству)

Уже сделано: библиотека слева и перетаскивание, панель свойств выбранного объекта, виды (3D, план, фронтальные), размеры на сцене, ведомость деталей, прайс по элементам.
Дальше: привязка к стенам и соседним модулям при свободной расстановке, окна и двери в помещении, фото-рендер для клиента, фасадные «наборы» (комплекты отделки уже есть).

## 5. Как подключить Битрикс в новом чате

1. В Битриксе есть входящий вебхук с минимальными правами (`crm`, `disk`, при необходимости `task`, `sonet_group`). После изучения его лучше отозвать.
2. Сервис `kitchen-api` запущен на Render, в его переменных окружения `BITRIX24_WEBHOOK_URL` и `RELAY_TOKEN`.
3. В среде Claude (облачная среда → Изменить): в «Разрешённые домены» добавлены `sofiya.bitrix24.ru` и адрес `kitchen-api-….onrender.com`; в «Сетевых секретах» секрет типа Bearer для этого адреса, заголовок `Authorization`, значение `RELAY_TOKEN`.
4. Настройки среды подхватывает только **новая** сессия. Проверка: `curl https://kitchen-api-c112.onrender.com/healthz` должно ответить `ok`, затем запросы вида `/bitrix/crm.category.list?entityTypeId=2` с токеном (токен подставляет прокси сам).
5. Бесплатный план Render усыпляет сервис: первый ответ идёт 30–60 секунд.

## 6. Что нужно от владельца

- Доступ или выгрузка 8–10 проектов из колонок «Отправленные», «Закупки», «Готово» (сметы, эскизы, файлы Базиса).
- Время технолога на проверку правил (раскладка ящиков и полок, добор, пенал с ящиками, колпаки, углы).
- Прайсы поставщиков: форматы файлов, как часто обновляются, нужны ли наценки по группам.
- Шаблон договора и график оплат, название бренда для документов.
- Хостинг и домен (Timeweb), кто администратор системы.
- Решение по ролям: только свои продажники или ещё дизайнеры-партнёры.

## 7. Известные ограничения прототипа

- SheetJS 0.18.5 для чтения Excel подходит для своих файлов, но не для чужих непроверенных: в рабочей системе файл разбирает сервер.
- Каталог в браузере ограничен 5 МБ localStorage, очень большой каталог не поместится (будет в базе).
- Цвет и текстуры декоров нужно подтягивать по артикулу из архивов поставщиков.
- Тесты вида и перетаскивания пока ручные (скриптами в браузере), автоматических в репозитории нет.
