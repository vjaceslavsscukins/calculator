# Калькулятор КП — карта проекта

Портал для салона мебели **CULTURA GROUP**: менеджер вставляет вывод **PRO100**, считает кухню или шкаф по прайсу (себестоимость → производство → розница), собирает **КП** для клиента (страница по ссылке и PDF), отправляет в WhatsApp / Telegram / Max, видит, что клиент открыл и спросил, печатает **спецификацию** к договору. Владелец и руководитель видят панель, все КП, правят прайс и коэффициенты.

С чего начать новому человеку:
1. Этот файл — что где лежит и как запустить.
2. `HANDOFF.md` — где портал работает (Timeweb, домен, база), переменные окружения, все решения владельца.
3. `ROADMAP.md` — что сделано и что дальше; `docs/ux-audit-2026-11.md` — разбор удобства.

## Главные правила (не нарушать)

- **Цена считается только в `engine/`** (функция `compute`). Сервер и интерфейс берут цифры из движка, сами не считают.
- **Менеджер не получает себестоимость, производственную цену, маржу и цены прайса** — сервер вырезает их (`api/src/lib/view.ts`: `viewFor`, `catalogFor`, `settingsFor`).
- **КП хранится снимком**: отправленная цена не меняется, когда меняется прайс или расчёт. Правка — «Новая версия».
- **Ключи и пароли — только в переменных окружения** (Timeweb), никогда в репозитории. Персональные данные клиентов — только на серверах в России.
- Деньги — в рублях без округления; округление только при выводе (`roundTo`).

## Как запустить у себя

Нужны Node 22.18+ и PostgreSQL 16+.

```bash
# база
createdb kp && createdb kp_test

# сервер (из kp-calc/api)
npm ci
DATABASE_URL=postgres://localhost/kp OWNER_EMAIL=owner@example.com OWNER_PASSWORD=owner12345 node src/server.ts
# → http://localhost:8787 (API); при первом запуске создаётся владелец и грузится стартовый прайс

# интерфейс (из kp-calc/web) — в другом окне
npm ci && npm run dev
# → http://localhost:5173 (запросы /api проксируются на 8787)

# или всё сразу в Docker: cp .env.example .env, заполнить, docker compose up --build
```

Тесты:
```bash
cd engine && npm test                                                   # движок
cd api && DATABASE_URL=postgres://localhost/kp_test npm test             # сервер (каждый файл — своя схема в базе)
cd web && npx tsc --noEmit -p . && npm run build                         # интерфейс: типы и сборка
```

## Как сделать типичные вещи

- **Новая группа прайса или новые позиции** — в портале: «Прайсы» → группа → «+ позиция» или «Загрузить прайс» (Excel / вставка). Новая группа целиком — миграцией (`api/src/migrations/0NN_*.sql`, `insert into catalog_groups …`) и в `data/catalog.json` для новых установок.
- **Новое правило расчёта** — только в `engine/src` с тестом в `engine/test`. Потом посмотреть, что вернётся в `viewFor` для менеджера.
- **Новый раздел сервера** — файл в `api/src/modules/`, функция `registerX(app, ctx)`, подключить в `app.ts`. Проверку доступа брать из `ctx`: `me`, `need`, `visibleClient`, `visibleCalc`.
- **Изменить базу** — новая миграция `api/src/migrations/0NN_название.sql` (старые не трогать): применится при следующем запуске.
- **Новая страница** — `web/src/pages/…`, маршрут в `web/src/main.tsx`, пункт меню в `web/src/components/Layout.tsx`, запросы — в `web/src/api.ts`.
