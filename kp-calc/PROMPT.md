# Калькулятор КП: промт для первой версии

Мини-продукт внутри репозитория «Конструктор кухонь». Живёт в папке `kp-calc/` и не зависит от прототипа `prototype/kitchen.html`. Задача — убрать ручную работу менеджера между PRO100 и коммерческим предложением, ничего не меняя в том, как он сейчас рисует кухню.

Этот файл — постановка задачи для разработчика (или для Claude в новом чате). Сначала владелец правит и дополняет его, потом по нему пишется код.

---

## 1. Как сейчас и что болит

1. Менеджер рисует кухню в **PRO100**.
2. PRO100 выдаёт потребность в материалах: площади (ЛДСП верх/низ, фасады верх/низ, ХДФ, м²) и штуки (петли, ручки, полкодержатели и т. п.). Пример такого вывода — лист «PRO100» в книге «Расчет ….xlsx» (см. `docs/bitrix-findings.md`).
3. Менеджер вставляет эти данные в Excel. Там форма калькулятора: по категориям (ЛДСП, фасады, столешница, фурнитура, подсветка, декор…) он выбирает материал из выпадающих списков, внутри книги лежат прайсы поставщиков (Кроношпан, Egger, МДМ, Эллион, фурнитура).
4. Из Excel он руками собирает КП, потом спецификацию (Приложение №2) и договор.

**Боль:** форма привычная, но сборка КП, спецификации и договора съедает много времени; себестоимость и наценки непрозрачны (коэффициенты 4,85 / 4 / 2,6 зашиты в книгу); прайсы обновляются вручную внутри файла.

## 2. Что делаем (первая версия)

Веб-портал (сайт), где менеджер проходит одну цепочку:

```
Вставил вывод PRO100 → Калькулятор (привычная форма) → Расчёт с себестоимостью и наценками
→ Коммерческое предложение → Спецификация (Приложение №2) → Данные для договора
```

### 2.1. Вставка из PRO100
- Поле «Вставить из PRO100»: менеджер копирует таблицу (Ctrl+C из PRO100 или из листа Excel) и вставляет. Также загрузка файла `.xlsx` / `.csv`.
- Программа сама разбирает строки: название позиции, количество, единица (м², шт, м.п.).
- Сейчас в книге количество из PRO100 только справочное, в расчёт менеджер вводит своё число. В портале количество из PRO100 подставляется сразу, менеджер может его поправить.
- Каждая строка сопоставляется с категорией калькулятора по таблице соответствий («ЛДСП_верх» → «Корпус, верх»; «Фасад_низ» → «Фасады, низ»; «Петли» → «Фурнитура, петли»…). Таблица соответствий — данные, её можно дополнять без программиста.
- Нераспознанные строки не теряются: показываются списком «Не разобрано», менеджер назначает категорию руками, программа запоминает выбор.
- Количества можно поправить руками; исправленное помечается.

### 2.2. Калькулятор (форма как в Excel)
- Блоки, как в листе «Расчет детальный»: **Нижний блок, Верхний блок (и антресоли), Столешница, Фурнитура, Подсветка, Декор, Стекло, Услуги** (доставка, монтаж, сборка, подъём).
- В каждой строке: категория → материал/позиция из прайса (поиск по названию и артикулу, фильтр по поставщику и коллекции) → количество → единица → цена закупки → сумма.
- Выбор материала один раз на блок (например, «Корпус низ: Egger W1000 ST9»), а не на каждую строку.
- Можно добавить произвольную строку (название, кол-во, цена) — для нестандартных позиций.
- Для одного проекта — несколько вариантов (например, «Эконом» и «Стандарт» с разными фасадами), чтобы показать клиенту сравнение.

### 2.3. Цены: себестоимость → производственная → розница (→ опт)
Как сейчас в книге (подробно в `docs/excel-calculator.md`): «Диллер» — закупка по прайсу, «Цех» — закупка × коэффициент строки (фактически цена клиенту), доставка и монтаж — 10 % от «Цех», «Запас» вводится в рублях, скидка не действует на доставку и запас. Первая версия должна сначала повторить эти цифры (эталонные тесты), потом переходим на уровни ниже.

Для каждой строки и для итога видны уровни цены:

| Уровень | Как считается | Кто видит |
|---|---|---|
| Себестоимость | закупка по прайсу × (1 + запас/отход) | руководитель, технолог |
| Производственная цена (цех) | себестоимость × коэффициент цеха по группе | руководитель |
| Розничная цена | производственная × коэффициент розницы по группе | менеджер, клиент |
| Опт / дилер | производственная × коэффициент опта | руководитель, по настройке |

- Коэффициенты задаются **по группам** (корпус, фасады, столешница, фурнитура, бутылочница/сушка, подсветка, услуги). Стартовые значения взять из текущей книги (около 4,85 / 4 / 2,6) после подтверждения владельцем.
- Скидка менеджера в % с лимитом (лимит задаёт руководитель), агентское вознаграждение, доставка, монтаж — отдельными строками, как в Excel.
- Маржа в рублях и процентах видна руководителю.
- Менеджер в обычном режиме видит только розничные цены; себестоимость — по настройке роли.
- Деньги в рублях, округление только при выводе.

### 2.4. Прайсы
- Прайсы поставщиков загружаются из Excel/CSV (мастер загрузки уже есть в прототипе, см. `docs/materials.md`, — переиспользовать идею: сопоставление столбцов, запоминание схемы по поставщику, обновление по артикулу, проверка до загрузки, откат).
- Каждая загрузка — версия прайса с датой. Расчёт фиксирует, по какой версии он сделан.
- Стартовый набор прайсов взять из скрытых листов текущей книги («Кроношпан», «Еггер», «ПВХ Эллион», «МДМ», «Прайс1», «Прайс Фурнитура»).

### 2.5. Коммерческое предложение
- Шаблон рисуем вместе с владельцем (отдельный шаг, см. раздел 6). Заготовка:
  - шапка салона, номер КП, дата, менеджер, клиент (имя, телефон — только то, что нужно);
  - картинка/эскиз кухни (менеджер прикладывает скриншот из PRO100);
  - **описание, что входит в кухню**, по блокам: «Нижние модули: корпус ЛДСП 16 мм Egger …, фасады МДФ эмаль …, ящики Blum LEGRABOX с доводчиком, петли Blum CLIP top BLUMOTION…», «Верхние модули…», «Столешница…», «Подсветка…», «Стекло…»;
  - цена по блокам и итог, скидка, доставка и монтаж, срок изготовления, условия оплаты, срок действия предложения.
- Тексты описания берутся из карточек материалов и фурнитуры (у позиции прайса есть поле «текст для КП»), а не пишутся заново каждый раз.
- Вывод: страница для печати и PDF, ссылка или файл для отправки клиенту.
- **КП сохраняется снимком**: после отправки цифры не меняются, даже если поменялся прайс. Новая версия КП — новый снимок.

### 2.6. Спецификация (Приложение №2)
Генерируется из того же расчёта, по полям нынешнего бланка:
- столешница; корпус и задняя стенка (материал, цвет);
- фасады низа, верха, антресолей (до 4 типов: материал, цвет, фрезеровка);
- ручки / Gola / TIP-ON (система открывания), количество;
- петли, направляющие ящиков, подъёмники, газлифты, штанги, выкатные корзины, карго, сушка;
- цоколь, подсветка, стекло;
- стоимость.
Разбивка «что относится к низу, что к верху, что к антресолям» берётся из блоков калькулятора. Менеджер может поправить текст перед печатью.

### 2.7. Договор
- В первой версии договор **не генерируем**: делаем выгрузку данных для договора (клиент, сумма, график оплат, номер спецификации) и, если удобнее, передачу в сделку Битрикс24, где договор собирается по шаблону Битрикса.
- Генерация договора в самом портале — следующая версия, если владелец решит.

## 3. Чего в первой версии нет

- 3D и рисование кухни (это делает PRO100, а позже — основной продукт).
- Деталировка, присадка, раскрой, выгрузка в Базис.
- Автоматическая запись в Битрикс24 (только чтение и, возможно, ссылка на сделку; запись — после согласования).

## 4. Технические требования

- Папка: `kp-calc/` в корне репозитория. Своя `README.md` с командами запуска и тестов.
- Стек: React + TypeScript (Vite), сервер — расширение `apps/api` (Node.js, PostgreSQL), как в основном продукте. Для самого первого показа допустим режим без сервера (данные в браузере + экспорт/импорт JSON), но расчёт сразу пишется так, чтобы переехать в `packages/engine`.
- **Расчёт цены — только в отдельном модуле чистых функций** (`kp-calc/engine/`, без React и без доступа к сети), с тестами. Интерфейс и документы берут цифры из него. Позже модуль переносится в `packages/engine`.
- **Эталон:** 3–5 реальных прошлых расчётов из Excel (без персональных данных) лежат в `kp-calc/engine/fixtures`. Тест: те же входные данные → та же сумма, что в Excel, построчно по блокам. Если тест падает — это баг расчёта, а не повод править ожидание.
- Разбор вставки PRO100 и прайсов — без `eval` и `new Function`; формулы (если понадобятся) — безопасным парсером, как в прототипе.
- Ключи (вебхук Битрикс24 и другие) — только в переменных окружения сервера.
- Персональные данные клиентов — только на сервере в России (152-ФЗ). До переезда на российский хостинг — вымышленные клиенты.
- Роли: менеджер, руководитель (прайсы, коэффициенты, лимиты скидок, маржа), технолог (просмотр себестоимости). Изменения прайсов и коэффициентов пишутся в журнал.
- Интерфейс на русском, кнопки называют действие («Вставить из PRO100», «Рассчитать», «Сформировать КП», «Скопировать спецификацию»). Работает на ноутбуке и планшете.

## 5. Критерии готовности первой версии

1. Менеджер вставляет вывод PRO100 из реального проекта, за 5–10 минут доходит до готового КП в PDF.
2. Сумма в портале совпадает с суммой в Excel на 3 эталонных проектах (по блокам и итогу).
3. Руководитель видит себестоимость, производственную, розничную цену и маржу по каждому блоку.
4. Спецификация (Приложение №2) печатается из того же расчёта без ручного перепечатывания.
5. Отправленное КП не меняется после обновления прайса.

## 6. Порядок работы

1. **Разбор материалов владельца** (раздел 7): вывод PRO100, книга Excel, пример КП, бланк спецификации. Составить таблицу «строка PRO100 → категория → формула цены».
2. **Движок расчёта** + тесты на эталонных расчётах.
3. **Вставка из PRO100** и калькулятор (форма).
4. **Прайсы**: загрузка стартовых прайсов из книги.
5. **Шаблон КП** — рисуем вместе с владельцем: 2–3 варианта макета на выбор, потом доводим выбранный.
6. **Спецификация** и выгрузка данных для договора.
7. Пилот с 1–2 менеджерами параллельно с Excel, замечания списком.

## 7. Что нужно от владельца (открытые вопросы)

1. **Пример вывода PRO100** из 2–3 реальных проектов: что именно менеджер копирует (отчёт, лист, файл) — в том виде, как он его вставляет в Excel.
2. **Текущая книга-калькулятор** (свежая версия) и 3 заполненных расчёта по реальным заказам — это эталон для тестов.
3. **Наценки:** коэффициенты 4,85 / 4 / 2,6 — это закупка × коэффициент = розница? Где здесь «производственная цена» (цех) и «дилер»? Что такое «запас» и «агент» в книге?
4. **Опт:** нужен в первой версии или позже? Кто его видит?
5. **Скидки:** максимальная скидка менеджера, кто согласует больше.
6. **КП:** есть ли сейчас пример КП, который нравится (или не нравится)? Логотип, реквизиты, фирменные цвета. Что обязательно писать (срок изготовления, гарантия, условия оплаты)?
7. **Спецификация:** актуальный бланк Приложения №2 (подтвердить, что поля из раздела 2.6 верные).
8. **Договор:** делаем в Битрикс24 по шаблону Битрикса или в портале? Нужен ли график оплат (аванс/доплата в %)?
9. **Кто пользуется:** сколько менеджеров, нужен ли вход по логину или хватит личного кода, как в прототипе.
10. **Где хостим:** пока Render (вымышленные клиенты), потом российский хостинг (Timeweb) — подтвердить.
